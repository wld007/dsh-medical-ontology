# 插件家族：从病历到本体与评测

> 本文件在 `dsh-medical-event`、`dsh-medical-ontology`、`dsh-medical-eval` 三个仓库里内容相同。
> 改动时三处同步（以 `dsh-medical-event/docs/family.md` 为准）。
> 文中 `../<目录>` 指与本仓库同级的目录（各仓库放在同一个父目录下）。
> 整理于 2026-11-11，来源是与用户的设计讨论；尚未写任何插件代码。

## 1. 要做的事

把一位患者多年的真实病历，逐层变成：

1. **可计算的事件**：每句话说了什么、什么时候写下、说的是什么时候的事、同一件事被说了几遍、哪些记录互相冲突。
2. **患者级临床本体**：以每一次治疗决策为节点，把病程组织成 人／诊／治／伴／归（＋检／影），并标明每次决策如何引出下一次。
   参照 G-MPAS 临床本体页 <https://www.g-mpas.com/ontology.html>。
3. **长病程临床推理评测集**：从本体派生 10 类任务（结局预测、临床决策、病程理解与归因、证据与时间纪律），在病程某一天截断出题。
   参照 G-MPAS 评测页 <https://www.g-mpas.com/eval.html>。

## 2. 四个插件，一条链

```
病历原始导出
  → 医疗数据匿名化  dsh-medical-anonymizer   （已有，../dsh-medical-anonymizer）
  → 病历事件还原    dsh-medical-event        工序 1–4：提及 → 类型 → 事件 → 矛盾
  → 临床本体构建    dsh-medical-ontology     工序 5–6 ＋ 本体组装：问题线 → 决策节点 → 闭环/伴发/归因/疾病关系
  → 长病程临床推理评测 dsh-medical-eval       工序 7–8 ＋ T01–T10：截断与防泄漏 → 出题 → 计分 → 跑模型
```

| 包名 | 中文名（侧栏） | 英文副标题 | Agent 工具前缀 |
|---|---|---|---|
| `dsh-medical-anonymizer` | 医疗数据匿名化 | Medical Data De-identification | `anonymize_` |
| `dsh-medical-event` | 病历事件还原 | Medical Event Reconstruction | `event_` |
| `dsh-medical-ontology` | 临床本体构建 | Clinical Ontology Builder | `ontology_` |
| `dsh-medical-eval` | 长病程临床推理评测 | Long-course Clinical Reasoning Eval | `eval_` |

“临床本体”在医学信息学里常被理解为 SNOMED 一类的术语本体；插件描述第一句要写明它是“患者级病程本体：以治疗决策为节点”。

## 3. 为什么这样拆（已论证，结论如下）

拆分标准是**复用价值**：每一段的产物都要像匿名化结果一样，能被多个下游直接拿去用。

| 产物 | 下游 | 复用面 |
|---|---|---|
| 匿名化后的病历 | 所有下游 | 最广 |
| **事件包**（工序 1–4） | 临床本体；评测 T05/T06/T09（不需要本体）；因果链标注的“装配”；病历质控；真实世界研究（用药暴露区间、检验结局）；患者时间线与病程摘要；抽取模型训练数据；带时间的病历检索 | 很广，不限病种 |
| 问题线、决策点（工序 5–6） | 只有本体、评测 T04、因果链标注 | 窄，且按病种定 → 不单独成插件，归本体 |
| **临床本体** | 评测其余任务、模型训练（世界模型）、医生标注、对外数据产品 | 广 |

拆开的代价及对策（讨论中明确过，必须遵守）：

- **下游经常发现上游的问题**（工序2 v2.2、工序3 v1.4 由工序4 试运行发现；工序3 v1.5 由工序8 发现；工序5 v1.1 的根子在工序1 的数据陷阱）。
  对策：三个插件的规则包、交接格式都带版本号；下游记录所用上游批次与版本，上游升版后下游提示“基于旧版，需重跑”。
  迭代期可以放在同一工作区一起改、一起发版。
- **交接格式还没定型**。对策：交接格式按“公开的、带版本的格式”设计；编号稳定；字段只增不改；消费者声明支持的版本。
- **按日期回看贯穿全程**（评测截断要求“截至 T 时刻”重算所有派生结论）。统一口径见 §4.4。
- **处处回得到原文**。对策：事件包自带片段原文与起止位置，下游不用回头读病历。

曾考虑过“一个插件内部分两段”（问题线以后才推断）。最终按复用价值拆成独立插件；推断与否不是插件边界，而是每条结论的“出处”标签（§4.5）。

## 4. 共同约定

### 4.1 继承自匿名化插件的做法（以它为模板）

参考 `../dsh-medical-anonymizer`：`README.md`、`docs/guide.md`、`AGENTS.md`、`lib/`、`client.js`、`cordis.patch.yml`、`design/`、`assets/dashboard.png`、`assets/review.png`。

- 绝不修改输入；写入前解析软链接，目标必须在本批输出内。运行前后核对源文件大小与修改时间。
- 输出根目录：交付数据直接放在根下，报告、批次记录、映射、缓存放 `_records/`（`runs/<runId>/report.md`、`report.json`、`calls.json` 等）。批次完成后交付数据才出现在根目录。
- 批次立即返回 `runId`；可取消、可从取消/失败处继续处理（复用已完成的模型调用）；分组处理大批量输入。
- 病历内容只发往用户在设置里配置的模型端点（通常本机或内网）；**Agent 工具不能选择端点、模型、API Key**；未配置模型时只跑规则。
- 规则是基线，模型可选；模型返回的位置一律不信，插件自己在原文里定位；有界修复，修不好转人工复核。
- 页面风格：深色 teal 控制室（与匿名化一致），标签页结构：产线 / 患者 / … / 复核 / 模型调用 / 日志 / 报告。
- 有批次在运行时不要重装、启用或停用插件（会中断批次）；改代码后用 `node scripts/build.mjs <版本>` 生成 `dist/<版本>` 再从 profile 安装，版本号 `0.x.y-dev.N` 递增（匿名化插件的 AGENTS.md）。

### 4.2 来自八道工序的原则（全部保留）

- **只按可见时间截断**：成文时间决定“当时能不能看到”；事件时间只用于叙事，不用于截断。
- **不做补全**：只基于现有数据，缺口如实标注，不推断未记录的事件。
- **处处回得到原文**：每条提及有片段内偏移 s/e，题面是按偏移切出的原文摘录。
- **规则化、可复跑**：每条记录写明命中的规则；派生结论可按截断点重算。
- **设计与结果分开**：每道工序的设计（规则、版本、修订记录）与本次结果分开交付。

### 4.3 稳定编号

旧结果里的 `M00001`、`E00001`、`F001` 按顺序编号，规则一改就移位，人工复核的裁定会对不上。新插件一律用内容派生的稳定编号：

- 片段：来源记录主键（+ 段落序号）派生；
- 提及：片段编号 + s + e 派生；
- 事件：成员提及集合派生（成员变了编号才变）；
- 发现、关系、归因：所涉对象编号 + 规则/类型派生。

人工裁定按稳定编号存“裁定表”，重跑时沿用。

### 4.4 按日期回看（as-of）

- 规则算出的派生结论：只用截止时刻以前写成的提及重新计算。
- 模型给出的判断：其可见时间 ＝ 所引证据中最晚的写成时间；截止时刻早于它就视为当时不知道。
- 日期对外一律相对化为 D+n（以首次确诊或约定锚点为 D+0），内部保留绝对时间。

### 4.5 出处与复核状态

每条结论（尤其是本体里的关系、伴发、归因）都带：

| 字段 | 取值 |
|---|---|
| 出处 | 原文写明（规则从原文抽出）／结构推出（按时间、同线计算）／模型判断（须引用提及编号并通过原文核对） |
| 依据 | 引用的提及编号列表 |
| 确定程度 | 规则确定／需人工确认 等 |
| 复核状态 | 未复核／已确认／已改判／驳回，复核人与时间 |

评测里“加工判断，需医生复核”的任务（T08、T09、T10）只能用已确认的条目出题。
这与因果链标注项目的口径一致：`basis_records`、`confidence`、`confirmed_by`（见 `../因果链标注/README.md`、`contracts/`）。

### 4.6 规则包分层

规则包按层组织，贯穿所有工序，不按工序切：

- **数据源层**：平台字段、文书类型与栏目、作废标记、时间字段陷阱；换医院/平台时改这一层。
- **通用医学层**：常见症状、检验别名、药名归一（商品名→通用名标“需药师复核”）。
- **专科/病种层**（可选）：血透包（干体重、透析方案、口服抗凝药互斥组、问题线词表）、肺癌包……换病种时改这一层。

不装专科包也要能跑：归不了一的概念标“未归一”照样交付。

## 6. 数据

- 区域平台导出 JSON：人口信息、就诊、诊断、检验、检查、病历记录、手术、费用（按月分文件）。字段名风格见匿名化插件的 `HEADER_HINTS`（如 `AXLR_EXAM`、`INVLD_FLG`、`CRT_TM`）。
- 302 名透析/CKD5 病人，按病人切分 训练 232／验证 30／测试 40；**HD-0001 永远只做测试**。
- 上游可以是匿名化插件的输出，也可以不是；不是时要在界面上明确提示。
